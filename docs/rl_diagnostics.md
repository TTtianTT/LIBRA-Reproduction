# RL 诊断协议

本轮目标是区分动作集合、物理模型误差与有限训练预算的影响。它是开发阶段诊断，全部新选择和评估只读取 Azure 第 1–9 天训练集与第 10–11 天验证集，**不重新打开历史测试分区**。历史测试结果已经影响问题的提出，后续泛化研究必须另设独立数据。

配置固定在 [`configs/rl_diagnostics.json`](../configs/rl_diagnostics.json)。运行产物和实际数值见 [`outputs/rl_diagnostics/REPORT.md`](../outputs/rl_diagnostics/REPORT.md)。现有论文仿真、RL-0、ML 和 PPO 历史源码及产物保持原样，不覆盖历史哈希。

## 动作与 DP

`libra_rl/diagnostic_env.py` 复用既有计费器与有限回合状态，新增联合 categorical 动作。v1 为 7 个残差目标与全 FaaS，共 8 个动作；v2 为 7×5 个目标/路由组合与全 FaaS，共 36 个动作。全 FaaS 的目标为零，立即缩容并正常支付所有 FaaS 调用费。它不会无偿保留温热 VM。

教师从已冻结的训练基线网格中选择：12 个 Quantile 候选里，训练违约率 ≤0.1% 且成本最低者。选择结果为 v1 的 ρ=1、v2 0.5s 的 ρ=0.7、v2 0.7s 的 ρ=0.6，历史窗口均为 300s。选择过程没有读取旧测试指标。原先的残差中心为 v1 的 ρ=1 与 v2 的 ρ=0.8。

`libra_rl/restricted_dp.py` 精确求解给定时间变化动作集合下的 C+λV，状态、冷启动、缩容和秒级计费与环境一致。对三个动作域分别计算：

1. 原中心 ±3，沿用路由网格；
2. 原中心 ±3，加全 FaaS；
3. 教师中心 ±3，加全 FaaS。

前两项具有包含关系，第三项更换了集合中心，不能声称集合单调扩大。以枚举和轨迹重放验证 DP；另外直接最小化违约数，检查动作限制是否使 SLA 根本不可行。

给定 λ 的解使用完整未来信息。有限 λ 扫描提供 ε 约束问题的对偶成本下界及已找到的可行成本上界，不等于精确求出每个 ε 下的最优离散计划。也不能把 oracle 的改善视作在线 RL 可以兑现的收益。

## 排队和历史失败重放

`libra_rl/queue_validation.py` 使用独立连续时间 FCFS 事件模拟，不调用 Erlang-C 公式。每项配置预热 50,000 个请求并测量 500,000 个请求；两个服务时间、五种利用率、两种服务分布、五个种子，共 100 次模拟。置信区间按独立种子的均值计算，不能将同一队列中相关的请求视作独立试验。

固定服务时间对应 M/D/16；旧 wait_budget 是指数等待尾和固定服务时间拼接的近似，并非 M/D/16 的精确分布。指数服务时间对应 M/M/16，使用完整响应时间公式。校准不包括非平稳队列累积、真实负载均衡、AWS 或 FaaS 延迟。

主学习诊断仍固定历史 wait_budget，便于隔离训练行为。因此这里的 SLA 结果只对该近似环境成立。后续如修改队列模型，应建立独立版本、重新冻结协议和对照，不根据 RL 是否获利决定采用哪种假设。

旧 `raw_actions` 0.7s、λ=0.01 的种子 1（失控）与种子 0（对照）在验证集重放，逐决策保存 VM、动作、成本、奖励、动作熵、critic value 和有限回合实际折扣回报。复查成本须匹配历史值至 1e-9，失败种子完整保留。观察到行为失控和 value 误差，不等于已经证明某个优化器错误。

## 训练与选择

先在恒定 32 req/s 的 v1 环境中，让五个随机初始化的 PPO 各训练 65,536 步。预先规定：四个更新后 checkpoint 选出的成本，其五种子平均相对规则 regret ≤1%，才运行主训练。

主训练为三场景 × 两初始化 × 五种子，共 30 条轨迹，每条训练 262,144 步，总计 7,864,320 步。toy 另用 327,680 步。两档预算共享轨迹，不把低预算再次加到实际样本数中。

| 预算 | 四个验证 checkpoint |
|---:|---|
| 65,536 | 16,384 / 32,768 / 49,152 / 65,536 |
| 262,144 | 65,536 / 131,072 / 196,608 / 262,144 |

随机初始化与规则先验使用相同代码、网络、动作、种子、预测器、增强、λ 和计算预算。规则先验将初始教师动作概率设为 0.9，初始贪心行为等于教师；这项能力是人为提供的先验，不能算作 PPO 学出来的能力。更新前的初始策略不参与四个学习 checkpoint 的选择。

λ 从验证集上教师动作域 DP 的可行候选中选，取成本最低者。这里使用 oracle 辅助挑 λ，本身就是需要披露的理想化调参选择；它也不能保证有限训练后的 PPO 满足约束。目标函数固定为成本+λ×违约数，γ=0.99，按旧协议归一化奖励。

每条轨迹另记录验证可行 fallback，候选包括教师、全 FaaS 与四个学习 checkpoint。它与 PPO 主结果分开报告，避免把退回规则策略包装成学习收益。

使用配对种子比较高低预算与不同初始化，给出均值和 Student-t 95% 区间。区间只度量种子差异，不包含验证工作负载的不确定性，也不消除验证集重复选择带来的偏差。更多样本不自动证明收敛。

## 运行和校验

```bash
.venv/bin/python scripts/rl_diagnostics.py --stage all --workers 4
.venv/bin/python scripts/summarize_rl_diagnostics.py
.venv/bin/python scripts/verify_rl_diagnostics.py --require-models
.venv/bin/python -m pytest -q
```

可使用 `--stage prepare/audit/bounds/queue/trace/toy/train` 重启对应步骤。重跑新协议应使用 `--output outputs/rl_diagnostics_replay`；运行后汇总与校验同样传此目录。源文件、数据和模型哈希不一致时拒绝混用。新 clone 没有 Git 忽略的历史权重，`trace` 步骤还需要先重建旧 PPO 研究中的两条 raw_actions checkpoint；缺失时会明确报错。

每个训练进程限制 Torch、OpenBLAS 与 sklearn OpenMP 为单线程，加载数值库后再验证线程池设置，避免进程并行和库内并行相互争抢资源。权重继续仅保存在本地；完整 JSON、CSV、图片与报告可纳入 Git。
